# Obsidian Command — teljes üzemeltetési és UX fejlesztési specifikáció
Dátum: 2026-11-18 | Címzett: implementáló AI / fejlesztő | Állapot: követelmény, nem készre jelentés
Kapcsolódik: master #12, aktív #173, AGENTS.md, OBSIDIAN-CANONICAL-IMPLEMENTATION-STATUS.md.
 
## 0. Kötelező végrehajtási szerződés
Az alábbiak saját termékkövetelmények, önálló implementációval. Kívánt működés és ajánlott implementációs megoldás külön kezelendő; ez nem forráskód vagy éles tesztbizonyíték. Az összes itt leírt funkciót vizsgáld meg, a már működőket tartsd meg, a hiányzó/részleges utakat fejezd be. Ne hozz létre párhuzamos implementációt meglévő bridge/service mellé. A kiadásra vonatkozó döntés a tulajdonosé; ez a dokumentum nem engedélyez éles műveletet.
- Először olvasd el az AGENTS.md, README, master #12 és #173 aktuális head/diff, Windows CI és kanonikus mátrix dokumentumait; a mátrix dátuma nem jelent automatikusan friss állapotot. Készíts ID szerinti kódtérképet (fájl/szimbólum/bridge, UI, native test, CI, valódi elfogadás), jelöld MEGVAN/RÉSZLEGES/HIÁNYZIK. Ne kezdj újra kész modult.
- A jelenlegi prémium React/TS UI, Windows WinForms/WebView2 .NET 10 host, shared wpf/Core és egyetlen Obsidian Preview verzió marad. Nincs új WPF UI, nincs SQL/DB-motor, nincs ClusterChat vagy Discord/chat relay (webhook értesítés külön megengedett). Az ASA és a Manager frissítése csak explicit kézi művelettel; passzív verzióellenőrzés megengedett, önálló letöltés/telepítés/restart nem.
- N-host/M-map/multi-cluster, lokális tulajdonos ír, peer megfigyelés hitelesített és read-only. Egy helyi mapot ne blokkoljon másik host offline állapota, kivéve ha konkrét shared művelethez bizonyítottan kell. Távoli műveleti gomb ne küldjön írást; az adott host saját Managerét mutassa. Egész cluster művelethez tervezhető csoport, de mindkét tulajdonos külön helyi végrehajtása kell. Későbbi távoli write külön architektúradöntést igényel.
- Meglévő Store-v1 világ, karakter, törzs, tribute, transfer adatok és zero-byte fájlok megőrzése. Nincs automatikus konverzió, törlés, új transfer gyökér/ID, fallback másik mentésmappára vagy lockok generikus felülírása. A már elfogadott működő játékbeli utazást ne minősítsd vissza önkényesen. Új backup/restore vagy migráció művelet külön bizonyítékot igényel. A futó ASA-t fejlesztői teszt nem érintheti.
- A normál üzemeltetési funkciók legyenek ténylegesen bekötve; ne legyen demo, mock siker, helyőrző bridge vagy örökké letiltott általános gomb. Csak konkrét állapotfüggő guard, pontos ok, javítási út és visszaellenőrzés. Ha nincs mérés, unknown, nem 0/Stopped. Titok, élő mentés, helyi érzékeny elérési út és valódi játékosazonosító nem kerülhet nyilvános GitHubra.
 
## 1. UX-01 — Dashboard, navigáció, gyorsgombok (P1)
Megőrzendő jóváhagyott PremiumDashboard.tsx, PremiumModBoard.tsx és fidelity CSS; négy KPI, maplista balra, host/események jobbra, opcionális mapgaléria. Bővítsd, ne cseréld le a kialakult kinézetet.
- Állandó fejléc: keresés, host/cluster/scope szűrő, kijelölt elemszám; Start, Stop, Restart, SaveWorld, Maintenance/Update, Scheduler, Ban Manager, Operations/Log, Settings. Tömeges művelet alapból csak explicit kijelölt helyi mapokra. Kijelölés mind / láthatók / törlés világos különbséggel; szűrőváltással scope ne táguljon csendben. Minden művelet előtt célok listája és a ténylegesen futó/elérhető elemek száma.
- Map sor vagy opcionális kompakt kártyanézet: map/logó, host neve (HP kék, Ryzen piros; további host konfigurálható), lifecycle státusz, RCON health és mérés ideje, játékosszám/max, CPU, RAM, uptime, Steam build, portok, ASA API állapot, következő ütemezés, utolsó mentés. Prioritás szerint rövidíts; részletek tooltipben, 125/150% Windows DPI-n sem levágott akciók.
- Helyi map gyorsműveletei pontos sorrendben: Start, Stop, Restart, SaveWorld, RCON, részletek/More. More: Backup Now, Dino Wipe, fájlmappák, Start API-val beállítás, Force Kill elkülönítve. Ikonhoz felirat/tooltip, accessible name, billentyűzet, fókusz; szín mellett szöveg. Click nem buborékol a sor navigációjára. Másik hostnál read-only státusz és tulajdonosnév, nem inaktívnak álcázott write.
- Map részletek: állandó címsor/státusz és gyorsgombok, oldalsó vagy csoportosított lapok: Overview, Launch, INI, Scheduler, SteamCMD, RCON, Players, Backup/Restore, Mods, ASA API/Plugins, Watchdog, Logs, Notifications, opcionális Beacon. Az adott map kiválasztása megmarad frissítésnél; natív művelet sikerét másik lap is frissítse, ne kelljen újranyitni. A részletekben legyen fájlútvonal megnyitás, nem jelszó-kijelzés.
- Műveleti központ: tartós per-map sor, korrelációs ID, fázis, kezdés/eltelt idő, queue pozíció, következő lépés és hibakód; összecsukható részletes idővonal. Befejezett eredmény bezárható, visszakereshető. Egy hiba ne tűnjön el toastként; összes célra success/skipped/busy/failed/unknown külön sor, aktív lock gazdája és hiba javítási útja. UI reconnect és Manager restart után journalból visszatöltés; soha ne replayeljen automatikusan parancsot.
Elfogadás: Playwright 1/5/10/20 map, 1/2/3 host, szűrés, 2 cél kijelölés, peer offline, busy, részleges siker, mapváltás, reconnect, 100/150% DPI. Kattintás pontosan egy típusos natív hívást eredményez.

## 2. LIFE-01 — profilok, telepítés, import, lifecycle (P0)
- Add Server varázsló: új telepítés / meglévő mappa / futó ASA felismerése; map official vagy custom, session name, install/SteamCMD útvonal natív folder picker, explicit save root, game/query/RCON port, max player, cluster, launch mód. Preflight mutassa a hiányzó komponenseket, javítás és status refresh. Profil törlése alapból nem töröl lemezen semmit.
- Folyamatdetektálás: regisztrált EXE kanonikus útvonala, parancssor, map/ports, PID+creation time és loader-child kapcsolat; PID újrafelhasználás, több azonos nevű EXE, idegen telepítés, lejárt peer snapshot kezelése. Reattach Manager restart után, ne induljon második ASA. Futó process != RCON ready. RCON timeout != process crash. Státusz: unknown, stopped, queued, starting, waiting-readiness, running/ready, degraded, stopping, maintenance, failed; desired/observed/verified mezők.
- Start: lokális ownership, lock, telepítés és portok protokoll szerint, pontos mentés/cluster útvonal, pending INI alkalmazása a megfelelő életciklusban, Loader vagy közvetlen ASA a profil szerint, indítás, PID identity, readiness probe. CPU affinity/prioritás csak a valódi processhez. RCON korlátozott backoff, timeout és pontos diagnosztika. Nem módosíthat automatikusan routert, tűzfalat vagy meglévő portokat.
- Stop dialógus három külön út: mentés+normál leállítás most; játékosfigyelmeztetés konfigurálható countdownnal, broadcast szöveggel és gyakorisággal; Cancel a shutdown commit előtt. Countdown után SaveWorld, meglévő natív journal szerinti ok-okozati SaveComplete és stabil mentés, DoExit, process tree és portok tényleges ellenőrzése. RCON offline vagy save evidence hiány ne legyen hamis siker. Kényszerítés csak külön egyértelmű veszélyjelzéssel és explicit engedéllyel vagy előre opt-in recovery policyval.
- Restart = szabályos stop, pending config, ugyanazon profilból start, readiness, opcionális késleltetett wipe csak a frissen indult PID/start identityre; ne legyen update belekényszerítve. Fázisváltásokat naplózd; timeoutnál ne váltson sikerre. Normál stop desired=stopped, Watchdog nem keltheti életre. Kézi Force Kill elkülönített utolsó lehetőség, csak ellenőrzött process tree.
- Helyi tömeges indítás/stop/restart: konfigurálható párhuzamosság és késleltetés, host RAM/disk korlát, ajánlott gördülő mód (következő map csak előző readiness + opcionális stabilizáció után, hiba esetén állj meg/indokolt skip). Explicit korábban stopped map ne induljon el maintenance végén engedély nélkül.
Teszt: hamis PID, identity mismatch, loader-child exit, duplicate start, partial RCON, mentési timeout, cancellation, host lekapcsolás, portütközés, stop-then-watchdog race, 5 map queue; valódi ASA disposable teszt és felhasználói acceptance külön.

## 3. JOB-01 — háttérütemező és összeütközés-kezelés (P0/P1)
Központi Scheduler Center + mapra szűrt nézet ugyanabból a tartós natív ütemezőből. A React tab bezárása ne állítsa le; teljes Manager kilépés esetén csak tényleges Windows háttérfolyamat/service mellett ígérhető futás. Mutasd a worker heartbeatet és a következő futást.
- Feladattípusok: SaveWorld; world backup; full local backup; profile/tribe/transfer backup ha igazolt; Restart; önálló Wild Dino Wipe (DestroyWildDinos); Custom RCON (templates); player broadcast; kézi maintenance indítása NEM időzített ASA update. Post-restart wipe külön kapcsoló és 0–600s delay, readiness binding. A post-restart wipe ne duplikálja ugyanazt a már teljesített slotot.
- Űrlap: név, engedély, target map IDs/host/cluster név és helyi scope, egyszeri dátum+idő, N perc/óra, napi idő, heti pipás hétfő–vasárnap külön időkkel, explicit time zone (Windows/IANA mapping, alap helyi), next run preview, figyelmeztetés üzenet/csatorna (serverchat/broadcast), figyelmeztetési pontok/lead time, opcionális wait-until-empty és maximum halasztás, timeout, stagger. Alapból semmilyen megszakító feladat ne legyen automatikusan bekapcsolva. Nem hardcode-olt 05:00 stb.
- Táblázat: típus, cél, schedule és zone, next/last, last result, enabled switch, Run now, Edit, Duplicate, Delete, History. Run now saját occurrence, nem reseteli a következő rendes slotot. Szerkesztésnél revision check. Egyéni hibás RCON sablon nem állíthatja meg a többi taskot.
- Tartós JSON/JSONL vagy meglévő persistence atomikus mentéssel, schema version/migráció, egyedi JobId/OccurrenceId (slot UTC + zone + target + job revision), claim/dispatch/result journal, bounded queue, idempotens claim. UTC tárolás és lokális megjelenítés, DST nem létező idő -> explicit skip/next valid policy; kettős óra -> egyszer fusson. Sleep/resume és kihagyott slot: default skip/record vagy egyszeri bounded catch-up a job policy szerint; nincs burst. Bizonytalan félbeszakadt művelet -> reconcile, nem automatikus replay.
- Egy map egy konfliktusos művelet. Kézi busy válasz tartalmazza az owner jobot; automatikus queue dedupe, prioritás UPS emergency > explicit biztonságos kézi műveletek / aktív lifecycle > restart > backup > save, custom RCON a parancs kockázata szerint. Aktív műveletet ne szakíts meg puszta prioritás miatt. SteamCMD/deployment/restore külön host/disk lock, holtpontkerülő sorrend. Külön mapok dolgozhatnak függetlenül. Konkurens backup és save összevonható igazolt friss SaveWorld evidence alapján, nem pusztán timestamp.
- Újraindítás/Manager update freeze: ne claimeljen új munkát átadáskor; journal és queue megmarad, feloldás után reconcile. Sem aktív, sem bizonytalan írás ne vesszen el. Remote peer offline nem blokkolja local scheduler.
Teszt: fake clock + natív worker; heti eltérő napok, egyszeri 1–2 perces cél, DST mindkét irány, restart közben duplikált tick, crash claim előtt/után, manual busy, deadlock, update freeze, 10 párhuzamos map, canceled countdown, PID váltás post-wipe előtt.

## 4. UPD-01 — SteamCMD, kézi karbantartás, cache (P1)
- Overview és SteamCMD lapon: Browse existing, Install SteamCMD, Check, Install ASA, Validate/Repair, Update, Stop+Update+Start. Egyértelmű hiányzó útvonal / EXE / hozzáférés / sérült bináris / network / disk hiba; ne keverd össze. Hivatalos Valve forrás, letöltés és kicsomagolás stagingbe, meglévő SteamCMD újrafelhasználása. App ID 2430930 ellenőrizendő hivatalos Steam dokumentáció alapján. Steam app manifest és remote build lekérdezés időbélyeggel; ellenőrzés nem frissít. Auto update és pre-launch update behívás tiltott a termékszabály szerint.
- Kézi update előnézet: local/remote build, szabad tárhely (staging + rollback + cél), célok és eredeti running state. Cache kulcs appid+branch+build+platform; ellenőrzött, változatlan build artifact, hostonként deduplikált download/preparation. Ne másold át másik map Saved/Config, cluster, mod vagy plugin mappáját; allowlist alapján csak szerverbináris/depot fájlok. Steam manifest konzisztencia és tényleges verzió validálása célon. Cache miss, remote build race, disk full, megszakadt fetch, update hiba esetén eredeti adat érintetlen, retry vagy rollback; részleges cache nem használható. Ha teljes bináris roll-back nem megoldható, ne állítsd hogy visszaállítható.
- Cache letöltési progress külön a map downtime-tól. Prepare amíg futnak a mapok csak ha igazoltan izolált; deploy/validate csak confirmed stopped target. Egy hoston korlátozott SteamCMD/deploy concurrency. Eredetileg futó target visszaindítása readiness ellenőrzéssel, más map nem indul. Red/green státusz natív megfigyelésből. Robocopy/SteamCMD exit code saját szemantikája, stdout/stderr, log buffer és cancel biztonságos ponton.
- Amazon Root CA/CRL ellenőrző eszköz opcionális explicit admin műveletként, hivatalos forrás, hitelesítés, állapot és pontos hiba; ne telepíts csendben tanúsítványt és ne kapcsold ki TLS ellenőrzést.
Teszt: két map ugyanazt a buildet kéri (egy fetch), eltérő build/branch, invalid cache, target config byte-identical, csak eredetileg aktív restart, storage error/rollback, újrakapcsolódó UI, SteamCMD valódi elkülönített telepítés.

## 8. BAK-01 — mentés, tárolási optimalizálás, restore (P0/P1)
Különböző mentéstípusok külön állapot és manifest: (a) világ + szükséges embedded Store/karakter/törzs, (b) profil/törzs export ahol ténylegesen külön állományok vannak, (c) local full recovery bundle (config, map saves, launch metadata, mods lista, API/plugin DLL/config az engedélyezett körben), (d) közös transfer/cluster adat koordinált mentése. Külső plugin DB nem Manager feature; ne állíts teljes DB konzisztenciát. Meglévő teljes mentést vagy restore kódot ne írd át csak optimalizálás kedvéért.
- UI Auto Save interval, Auto Backup type/schedule/target, Save before backup, választható cél mappa, retention külön world/profile version/count/age, disk quota, skip unchanged, recent verified save window (javasolt 5 perc, 0=új save), Backup Now, Browse/Open, Verify, Restore Preview, Restore, Delete. Backup Now kötelezően új, teljes logikai snapshot; kihagyás csak scheduled, tényleges összehasonlításon. Semmit nem törölni a live save rootból. Optional rolling/anti-corruption extra backup include/exclude csak külön bizonyított inventory, alapból teljes biztonságos mentés; kizárás nem jelent live fájltörlést. A teljes szükséges állománylista Store-v1 típusonként explicit, zero-byte is adat.
- Optimizálás: izolált offline forrásnál közvetlen olvasás és tömörítés egy staging archive-ba teljes temp másolat helyett. Forrás fájlokat read-only módon nyisd, ne akadályozd az ASA-t. Élő backup csak ha támogatott konzisztencia-módszer és teljes inventory/SaveComplete/readiness bizonyított; különben szabályosan stopolt snapshot vagy dokumentált konzisztens fájlrendszer-snapshot. Nyitott file önmagában nem bizonyít konzisztenciát; több fájl közötti Store/transfer tranzakció consistency külön szükséges. Before/after fingerprint méret/idő/hash és mappainventory, változás/lock -> bounded retry vagy explicit failure; soha ne publikálj félig kész archivumot. Nem követeld a másik termék saját mérésének másolását; mérd a saját bytes-written, duration, size és retention eredményeket.
- .partial unique + manifest (schema, backupId, source identity/relative paths, flags, file sizes/hashes incl empty, create time, save evidence, scope, verification status), archive reread/CRC/hash ellenőrzés, durable flush, atomic rename/same-volume publication, crash recovery quarantined partial. Unchanged detection teljes required file inventory és checksum/korrekt fingerprint alapján. Profile verziók deduplikálhatók de restore referenciák/retention GC ne töröljenek szükséges tartalmat. Utolsó valid backup automatikusan ne törlődjön. Retention csak sikeresen verifikált új mentés után; disk full ne pusztítsa a régit. SMB elérés/credential külön; nincs automatikus local fallback.
- Restore: lista dátum/típus/source hash/verified/size; map/host/cluster identity; archive path traversal/reparse/zip bomb guard, target stopped pozitív igazolás ahol felülírás történik, karakter offline és Store-specifikus korlátozás (embedded Store esetén nincs hamis standalone profile restore). ## 19. Implementáció és Definition of Done
Végrehajtási sorrend: P0 lifecycle/identity/Store invariants/backup/restore/update handoff → P1 job engine és lock, SteamCMD/cache, Watchdog, API/mod/config, UX/notification → P2 admin/authorization/polish → P3 opcionális integrációk. Az összes munkacsomagra készíts evidence sort, de ne állítsd le a többit egyetlen P0 helyszíni teszt hiánya miatt; forrásimplementáció és isolated teszt folytatható. P3 külső függőséghez (UPS hardver, Beacon account, signing identity, plugin licence) legyen működő local UI, validation, mock/contract teszt és explicit valódi elfogadási blocker; ne jelents hamis kész integrációt. 
Minden ID-nál: [ ] meglévő source audit; [ ] backend typed route + permission + native operation; [ ] React valódi binding; [ ] unit/native negative és concurrency tests; [ ] UI Playwright; [ ] Windows packaged CI pontos SHA; [ ] release/installer evidence ahol releváns; [ ] disposable ASA és tulajdonosi live acceptance ahol szükséges. A teszt nem csak gomb jelenlétét, hanem native argument, invocation count és actual outcome-t igazolja. Kanonikus mátrix frissítése, meglévő tesztek megtartása, regresszió javítása; master #12 alatt koordináld. Aktív #173 munkát ne írd felül vagy duplikáld: várakozó CI és hiányzó native watchdog/schedule/full backup/release acceptance az aktuális head alapján ellenőrzendő. 
Késznek csak a tényleges működő kód és tesztek megléte esetén jelölhető; CI nem tanúsít automatikusan éles ASA működést. Live acceptance tényleges felhasználói bizonyíték külön, production adat nem tesztfixture. Ne publikálj vagy telepíts release-t pusztán ennek a dokumentumnak a létrejöttétől.
