# Untamed Manager Premium UI — Windows x64 TEST (v1.6.1 · Neon Kingdom TEST 8)

> Separate Windows test PC only. Not certified for production ASA, Store, or SQL writes.

This prerelease is built from the existing PR #7 project, not a replacement product.
The ZIP and Setup are generated by Windows GitHub Actions only if the complete
WPF boot, isolated FakeASA integration, MariaDB sandbox, screenshot rendering
and updater rollback tests pass. SHA256SUMS.txt identifies every binary exactly.

## Neon Kingdom TEST 11 — stopped-only Steam update and initial RCON

This is an incremental REAL manager integration, not a new demo application:

- The new ASA wizard no longer forces RCON off in the launch arguments.
  When the operator supplies a new 12+ character admin secret, only a NEW
  `ShooterGame/Saved/Config/WindowsServer/GameUserSettings.ini` is created
  with RCON enabled and the chosen TCP port. Existing/imported INIs are
  NEVER overwritten. The password is not added to the process command line.
  ASA itself requires the plaintext password in that server INI.
- A registered, independently **confirmed stopped** ASA map can now use its
  own manual **Frissítés telepítése** button. It requires affirmative
  confirmation, verified stopped world/INI/plugin backup, enough local disk
  capacity, the installation-specific OS operation lock, and a durable
  machine-local serial queue. It runs the real SteamCMD 2430930 child,
  verifies its result and compares SHA-256 of all protected saved/plugin
  files before and after. It does NOT stop, start or restart the map.
- The one-click command in Steam Update Center processes only verified
  outdated/stopped locally owned maps. Multiple maps on the same ASA
  installation are grouped into one file update. A failed map prevents all
  remaining local updates; interrupted work remains NeedsOperator.
- Failures do not automatically restore a backup onto a potentially
  changed world. Review the verified backup and local journal manually.
- Windows CI uses a harmless FakeSteamCMD executable with real child-process
  I/O and synthetic world/INI/plugin data. It proves the Manager's
  fail-closed flow, **not live ASA/Valve CDN interoperability**.
- A running ASA server is still NOT automatically stopped or restarted.
  The available ASA API SDK exposes save-start and save-finished delegates
  on AShooterGameMode. However, a version-matched, authenticated plugin
  emitting operation-specific post-flush evidence still needs a separate,
  real isolated Windows ASA acceptance test before this can be used to
  unlock SaveComplete/DoExit/Restart. The production Store-v1 writer,
  character transfer and SQL recovery likewise remain gated.
- Both UK-HOME Managers update independently; no inter-host
  maintenance lease, queue or peer approval is permitted.

## Local SteamCMD queues — two independent Windows hosts

UK-HOME-01 and UK-HOME-02 run their own Untamed Managers. **Each Manager
updates only its locally registered ASA maps**, one map at a time. Both
physical Windows hosts may perform maintenance simultaneously. The peer
Manager being offline, busy, or performing its own updates must never
block local maintenance. No two-host operation ID, leader election,
cluster-wide lease, approval handshake or shared update queue exists.

On each individual Windows host, the existing machine-local named
Steam queue semaphore, persistent queue journal, process checks,
shared-install running-map protection and per-installation operation
coordinator remain in place. They prevent concurrent maintenance
within that Windows machine and stop unsafe retries after interruption.
The authenticated LAN GET_STATUS connection continues to carry
**read-only** remote map and Steam build information. It does not accept
remote Steam update commands.

Separate release safety restrictions remain: real ASA SaveComplete,
validated backup, controlled process stop, post-update readiness and
character/Store-v1 preservation have not been accepted on a live
isolation server. The production live-update capability gate stays closed
for those reasons, **not** because of any two-host coordination.

## Neon Kingdom TEST 8 — additional map setup workflow

The real five-step **Add Local ASA Map** editor includes an explicit
**Detect ASA EXE + API loader** control. It only inspects the exact selected
`ShooterGame/Binaries/Win64` folder, never launches either binary and
never scans the user's drives automatically. Operators still supply each
map's actual launch arguments and correct ports.

On step 5, **Review**, the Manager validates the local server EXE,
installation root, watchdog period, optional ASA API loader, and UDP
Game/Query plus TCP RCON port collisions with other **local** maps.
Save remains disabled until these preliminary checks pass and repeats
all checks when clicked. A remote peer's map data is never treated
as local ownership. Synthetic integration tests cover read-only discovery,
TCP/UDP collision rules and original-file preservation.

Local map add, edit and removal now use rollback-safe configuration
transactions; failed writes do not leave phantom map registrations or
partially edited profiles in memory. This does not enable production
ASA launch or character/Store writes.

## What's new in the next Neon Kingdom visual test

- The REAL Dashboard uses a full-width ARK hero and illustrated local/cluster map tiles.
  The map source, host, players and status are bound to actual Manager data, not to the painting.
- The KPI grid now responds to *measured content width*: four columns where available,
  two on medium widths and one when needed for high-DPI small desktops.
- The server-add editor is a five-step, resizable WPF wizard with EXE/folder browsing,
  fixed Back/Next/Save/Cancel footer, local validations and no implicit server start.
- Native screenshots now cover **all five steps** of the real editor,
  and the gallery tests a WPF MouseWheel event on the illustrated Dashboard.
- Password boxes (RCON, LAN pairing, CurseForge API key) share the dark accessible
  graphite theme; no unstyled white password field should remain.
- The live Mod Center can request one configured CurseForge project by its
  exact ID; the returned project is rejected unless the authenticated API
  confirms it belongs to ARK: Survival Ascended. No download occurs.
- Map add, remove and edit now restore the original in-memory map list on
  ConfigStore optimistic-lock (CAS) or I/O failure; the five-step wizard
  stages a complete copy rather than mutating the live profile before Save.
- The Dashboard and other long workspaces now have opt-in real WPF wheel
  forwarding. The top-level page only takes over when a nested list cannot
  scroll in the requested direction. Both top-level wheel routes have
  Windows runtime screenshot tests.
- The CurseForge catalog now displays allowlisted HTTPS artwork; configured mods
  only receive a name and thumbnail after an authenticated provider response.
  These are display metadata, not proof of installation or crossplay compatibility.
- Mod and Plugin Center rows have visual state indicators but retain their existing
  guarded operations, previews and safe persistence rules.

### What is **not** certified

Production ASA SaveComplete/Start/Stop/Restart, authenticated Store-v1 writers across
both nodes, live character transfer, live MariaDB restore and full multi-host
recovery still need isolated real-server acceptance. Windows CI, FakeAsa and
synthetic SQL tests **do not** certify those capabilities. Keep hard gates enabled.

## First launch

1. Use a **separate Windows 10/11 x64 test machine**. Do not install on UK-HOME-01 or UK-HOME-02.
2. Launch the application and verify splash, main window, sidebar and tray icon.
3. Click **DEMO** in the top bar or start with `UntamedManager.exe --demo`.
4. Explore ten fictional ASA maps on three simulated hosts; test start, stop,
   restart, mod modes, plugin toggles, INI preview, RCON fixture, backups and schedules.
5. Exit DEMO. The demonstration data disappears; the actual local profile remains unchanged.
6. At 1366×768, 1600×900, 1920×1080 and Windows display scaling 125%/150%,
   check sidebar focus/hover/selection, scroll, title clipping, and map cards.
7. For actual non-DEMO operations, register only a disposable local map in a
   lab profile. Never point this prerelease at live cluster directories.

## Safety scope and evidence

- The live dashboard does not invent CPU/RAM, process, player, RCON, or backup states.
  Manager-profile drive statistics are explicitly labeled, not claimed to be
  measurements of every ASA volume.
- The mod inventory shows local startup-argument configuration; it does not
  claim that a CurseForge mod is installed or loaded in-game.
- DEMO is entirely in memory and never sends real RCON, ASA, Store, SQL,
  network or server-lifecycle commands.
- Store-v1 data and character files are not converted. Unsafe production
  operations remain guarded by the existing release capability checks.
- Dynamic N-host production operation and all T01–T34 workflows are **not**
  certified finished by this visual/test preview.
- GitHub Actions verifies rendered layouts at the three requested viewport
  sizes. Actual Windows 125% and 150% display-scale acceptance still needs
  hands-on testing on the dedicated Windows PC.
