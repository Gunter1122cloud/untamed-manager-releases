# Untamed Manager Premium UI — Windows x64 TEST (v1.6.1 · Neon Kingdom TEST 8)

> Separate Windows test PC only. Not certified for production ASA, Store, or SQL writes.

This prerelease is built from the existing PR #7 project, not a replacement product.
The ZIP and Setup are generated by Windows GitHub Actions only if the complete
WPF boot, isolated FakeASA integration, MariaDB sandbox, screenshot rendering
and updater rollback tests pass. SHA256SUMS.txt identifies every binary exactly.

## What's new in the next Neon Kingdom visual test

- The REAL Dashboard uses a full-width ARK hero and illustrated local/cluster map tiles.
  The map source, host, players and status are bound to actual Manager data, not to the painting.
- The KPI grid now responds to *measured content width*: four columns where available,
  two on medium widths and one when needed for high-DPI small desktops.
- The server-add editor is a five-step, resizable WPF wizard with EXE/folder browsing,
  fixed Back/Next/Save/Cancel footer, local validations and no implicit server start.
- Native screenshots now cover **all five steps** of the real editor,
  and the gallery tests a WPF MouseWheel event on the illustrated Dashboard.
- Password boxes (RCON, LAN pairing, CurseForge API key) share the dark accessible
  graphite theme; no unstyled white password field should remain.
- The CurseForge catalog now displays allowlisted HTTPS artwork; configured mods
  only receive a name and thumbnail after an authenticated provider response.
  These are display metadata, not proof of installation or crossplay compatibility.
- Mod and Plugin Center rows have visual state indicators but retain their existing
  guarded operations, previews and safe persistence rules.

### What is **not** certified

Production ASA SaveComplete/Start/Stop/Restart, authenticated Store-v1 writers across
both nodes, live character transfer, live MariaDB restore and full multi-host
recovery still need isolated real-server acceptance. Windows CI, FakeAsa and
synthetic SQL tests **do not** certify those capabilities. Keep hard gates enabled.

## Which file to download

- `UntamedManager-1.6.1-premium-SETUP.exe` — normal per-user Windows installation.
- `UntamedManager-1.6.1-premium-portable.zip` — unzip **all** three included
  executables to the same directory and launch `UntamedManager.exe`.
- `UntamedManager-WPF-v1.6.1-premium-test.exe` — standalone EXE for inspection.
  For actual portable use, take the ZIP because updater and supervisor are separate.
- `UntamedManager-premium-dashboard.png` — actual WPF runtime screenshot.

## First launch

1. Use a **separate Windows 10/11 x64 test machine**. Do not install on UK-HOME-01 or UK-HOME-02.
2. Launch the application and verify splash, main window, sidebar and tray icon.
3. Click **DEMO** in the top bar or start with `UntamedManager.exe --demo`.
4. Explore ten fictional ASA maps on three simulated hosts; test start, stop,
   restart, mod modes, plugin toggles, INI preview, RCON fixture, backups and schedules.
5. Exit DEMO. The demonstration data disappears; the actual local profile remains unchanged.
6. At 1366×768, 1600×900, 1920×1080 and Windows display scaling 125%/150%,
   check sidebar focus/hover/selection, scroll, title clipping, and map cards.
7. For actual non-DEMO operations, register only a disposable local map in a
   lab profile. Never point this prerelease at live cluster directories.

## Safety scope and evidence

- The live dashboard does not invent CPU/RAM, process, player, RCON, or backup states.
  Manager-profile drive statistics are explicitly labeled, not claimed to be
  measurements of every ASA volume.
- The mod inventory shows local startup-argument configuration; it does not
  claim that a CurseForge mod is installed or loaded in-game.
- DEMO is entirely in memory and never sends real RCON, ASA, Store, SQL,
  network or server-lifecycle commands.
- Store-v1 data and character files are not converted. Unsafe production
  operations remain guarded by the existing release capability checks.
- Dynamic N-host production operation and all T01–T34 workflows are **not**
  certified finished by this visual/test preview.
- GitHub Actions verifies rendered layouts at the three requested viewport
  sizes. Actual Windows 125% and 150% display-scale acceptance still needs
  hands-on testing on the dedicated Windows PC.
